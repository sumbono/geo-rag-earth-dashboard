## Method & disclosures

- Budgets (PLAN.md §5): text→embedding < 400 ms, pgvector search < 50 ms, end-to-end `/search/vector` p95 < 800 ms. PASS = strictly under budget (p95 == budget counts as FAIL).
- Statistics: arithmetic mean; p95 = nearest-rank (sorted sample, index ceil(0.95·n)−1, no interpolation).
- Each leg: 3 warm-up iterations discarded, then 50 measured iterations over a fixed cycle of 6 earth-observation queries.
- Encoder `remoteclip`: constructed once in 6775 ms (model load excluded from (a) timings; warm-up absorbs first-call cost).
- SQL leg: the real `ORDER BY embedding <=> … LIMIT 12` statement (mirrors `app/routers/search.py`) executed on a per-iteration pooled Session against `postgresql+psycopg://postgres:postgres@localhost:5432/geo` — 100 tile rows (fixture seed `fixtures/seed.sql.gz`); one query embedding reused across iterations so this isolates the search.
- e2e leg: httpx POST `http://localhost:3000/api/search/vector` with a cookie session from `POST /auth/token` — the browser path (web `/api` proxy → api → db). The stack ran with its compose settings (rate limit on); n+warm-up stays under the 60/min search limit. Warm-up discards run before sampling; the api's one-time model load happens at most once per process (R15: encoder memoized) and never inside a measured sample. Path caveats and code-state notes live in the author-maintained methodology section below, preserved verbatim across runs.

## Methodology notes (static, author-maintained)

- Path measured: browser path (web `/api` proxy → api → db) minus Traefik/TLS, which local compose does not run.
- Encoder lifecycle: since R15 (commit ac62f7d) the api process memoizes its encoder — constructed on first use, reused for every later request — so warm-up discards absorb the one-time model load. Before R15 the encoder was constructed per search request; that defect is the subject of History below.
- The machine line's date is derived from run time; everything above this marker is regenerated by `apps/api/scripts/bench.py` on each run, everything from the marker down is preserved verbatim.

## History

- Initial run 2026-10-07: e2e mean 2035.1 ms / p95 2294.6 ms — **FAIL** vs < 800 ms budget (encode p95 90.0 ms PASS, SQL p95 3.6 ms PASS). Root cause: `search_vector` constructed a fresh `RemoteCLIPEncoder` on every request (~2 s model load each call); found by the Task 23 honest benchmark, ruling R15.
- Memoized fix: commit ac62f7d (`get_encoder` process-level singleton, keyed by `(encoder, device)`, lock-guarded).
- Re-run 2026-10-07 (post-fix, same command, n=50): e2e mean 102.4 ms / p95 181.8 ms — **PASS** vs < 800 ms (encode p95 126.6 ms PASS, SQL p95 3.8 ms PASS). Consecutive-search check on a freshly rebuilt api: first request 14.6417 s (one-time model download+load), second 0.1659 s, third 0.0889 s — the encoder is reused, not reloaded per request.
